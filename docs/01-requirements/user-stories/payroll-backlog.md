## 0. Ownership boundaries used for sizing

**Built in this backlog (Payroll owns the payroll engine end to end):**
- The **YourHRM Formula Language (YFL)**: parser, type checker, exact-decimal evaluator, sandbox, DAG (ADR-0008). *Note for the PM:* estimation-guide §2 lists "formula engine" under the technical-enablers backlog. By assignment, YFL is built and estimated **here**; the TECH backlog should estimate only hosting it as a shared module for other hosts (workflow conditions, eligibility rules), not the language itself, to avoid double counting.
- Run orchestration: state machine, input snapshot, partitioning into parallel chunks, finalisation, versioned kernel and reproduction (ADR-0009). The **generic job queue / scheduler** (ADR-0011, BR-SAAS-090) is TECH/SaaS; Payroll registers its `payroll` pool and job types only.
- Components, structures, pay scales/bands, pay groups and calendars, standard-day methods, all gross-to-net calculation, insurance, PIT, statutory files, payments, GL, loans, payslips, retro, off-cycle and final settlement, and the Payroll **opening-balance templates** (YTD income/PIT/SI, SI contribution history, loans).
- The golden test pack (≥ 200 scenarios, NFR-PAY-008).

**Consumed, not built here (only registration/configuration is counted):**
- Legal Parameter Service storage, pack lifecycle and admin UI: SaaS (PR-06, ADR-0010). Payroll is a read client and snapshots values per run.
- Core: workflow engine, import engine (BR-CORE-110..114), document/PDF service (ADR-0015), notification centre and e-mail delivery, audit store, RBAC/data scopes.
- SaaS: ESS shell, job scheduler, cut-over/lock and adjustment batches (BR-SAAS-088/089), the **one-month payroll comparison (BR-SAAS-073)**, object storage, tenant keys.
- People: salary record, contracts, dependants, residency, SI enrolment and participation, salary-history template (BR-SAAS-069 assigns it to People). T&A: Attendance Result, close-hold API, holiday calendar.

**Dependency tags.** Other backlogs were not yet published when this file was written, so cross-backlog dependencies use tags: `TECH:<enabler>`, `CORE:<capability>`, `SAAS:<capability>`, `PPL:<capability>`, `ATT:<capability>`. The PM replaces them with `US-…` IDs at consolidation.

**Legal uncertainty rule (guide §4).** Where a `[verify-legal]` rule is still unclear (open questions Q1, Q3, Q11 in the BRD; R3-02, R3-03 in the decision log), the story was raised one Fibonacci step and is marked `[high-uncertainty]`. Where the rule is clear and only the value is `[verify-legal]` (values are parameters anyway), no step was added.
